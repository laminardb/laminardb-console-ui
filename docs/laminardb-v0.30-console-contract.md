This is the implementation contract used by this console. It is deliberately pinned to an engine commit: the `0.30.0` workspace version is not, by itself, a sufficiently precise compatibility boundary while `main` continues to change.

## Compatibility summary

The console supports the HTTP and browser WebSocket surface at the exact commit above. It treats all Rust `u64` values and all exact-integer Arrow JSON fields losslessly, warns when `/health` reports a version other than `0.30.0`, and does not infer compatibility from that version warning alone.

There is no engine build-SHA field in `HealthResponse`, so a browser cannot prove that a connected `0.30.0` binary is this exact commit. Operators must pin the server artifact outside this protocol. A differently built `0.30.0`, a feature-reduced binary, custom connectors, or a later `main` commit is best-effort and may require a new contract review.

## JSON and SQL contract

### HTTP SQL responses

`SqlResponse` has `result_type` and these variant fields:

| `ExecuteResult` | HTTP fields | Source file and Rust type/function |
| --- | --- | --- |
| `Ddl(DdlInfo)` | `result_type = statement_type`, `object_name` | [`ExecuteResult`, `DdlInfo`][execute-result], [`catalog::execute_sql`][catalog-http] |
| `RowsAffected(u64)` | `result_type="rows_affected"`, `rows_affected` | [`ExecuteResult`][execute-result], [`catalog::execute_sql`][catalog-http] |
| `Metadata(RecordBatch)` | `result_type="metadata"`, `data` | [`ExecuteResult`][execute-result], [`catalog::execute_sql`][catalog-http] |
| `Query(QueryHandle)` | `result_type="query"`, `data`, and `truncated=true` only when capped/timed out | [`catalog::SqlResponse`, `MAX_SQL_RESULT_ROWS`, `SQL_RESULT_TIMEOUT`][catalog-http] |

HTTP query collection stops at 1,000 rows or after 5 seconds and returns the collected prefix with `truncated=true`. HTTP SQL explicitly rejects both direct `SUBSCRIBE` and `DECLARE CURSOR FOR SUBSCRIBE`; those belong to pgwire. [`LaminarDB::execute`][db-mod]

Arrow JSON uses explicit `null` fields. `Int64`, `UInt64`, and decimal values are encoded as decimal strings; non-finite floats are strings. This avoids JavaScript precision loss in tabular SQL/checkpoint output. Direct serde control-plane `u64`s can still be JSON numbers, so the console uses lossless JSON parsing before normalising them to decimal strings. [`json_encoding::exact_json_encoder_options`][json-encoding]

The REST catalog intentionally exposes only sources, sinks, streams, MVs, the lineage graph, and compiled streaming connectors. Tables, lookup tables, query execution plans, and connector delivery contracts do not have dedicated REST catalog shapes at this commit.

### AI SQL

The eight registered marker UDFs are `ai_classify -> Utf8`, `ai_sentiment -> Float64`, `ai_embed -> List<Float32>`, and `ai_extract`, `ai_complete`, `ai_summarize`, `ai_translate`, `ai_gen -> Utf8`. Markers are registered as known SQL functions, but actual inference needs `[ai.providers]`, `[ai.defaults]`, and `[models.*]` runtime configuration; an un-rewritten marker errors if evaluated directly. Remote inference is behind the `laminar-db/remote` Cargo feature and local inference behind `laminar-db/local`; the server dependency enables `api`, `remote`, and `local`. Cluster query admission rejects AI state because it lacks a vnode-keyed rebalance lifecycle. There is no AI HTTP endpoint. ## Cluster lifecycle and assignment ABI

`NodeState` has exactly `Joining`, `Active`, `Suspected`, `Draining`, and `Left`. `NodeInfo` is `{id: NodeId(u64), name, rpc_address, state, metadata, last_heartbeat_ms}` and `NodeMetadata` is `{cores, memory_bytes, failure_domain, tags, version}`. It has no Raft fields and no owned-partition list. Only `Active` nodes are assignable. [`NodeState`, `NodeMetadata`, `NodeInfo`, `assignable_node_ids`][discovery]

`AssignmentSnapshot` is:

```text
version: u64
partitioning_abi_version: u16
vnodes: BTreeMap<u32, NodeId>
participants: Vec<CheckpointParticipant>
updated_at_ms: i64
draining: bool
drain_transition: Option<AssignmentDrainTransition>
```

The drain transition binds predecessor and target `CheckpointAssignmentFence`s plus `LeaderProof`; participant identities include node ID and boot incarnation. The partitioning ABI constant is `2`. Key groups are a typed range `1..=65535`; the common default is 256, but `[server].key_groups` is mode-neutral and configurable, so the console derives cardinality from the returned map rather than assuming 256. [`AssignmentSnapshot`][assignment-snapshot], [`AssignmentDrainTransition`, `CheckpointAssignmentFence`, `CheckpointParticipant`, `LeaderProof`][checkpoint-assignment], [`KeyGroupCount`, `PARTITIONING_ABI_VERSION`, `DEFAULT_KEY_GROUP_COUNT`][vnode]

Direct serde control-plane node, assignment, fence, and term IDs may exceed JavaScript's safe integer range. They are parsed losslessly and rendered as decimal strings by this console.

Pipeline `start`/`stop` acts locally first. In cluster mode, omitting `local=true` sends concurrent fire-and-forget requests to known peers; peer errors are logged and do not fail the initiating response. A successful response proves only the local operation, not cluster-wide convergence. [`fan_out_pipeline_control`][cluster-admin]

### Browser WebSocket

### `AS OF EPOCH` and pgwire

| Transport | `AS OF EPOCH` | Other subscription clauses/constraints | Source file and Rust type/function |
| --- | --- | --- | --- |
| Browser WebSocket | Yes, query `as_of_epoch=u64`. | No server-side `WHERE`; no application client messages. | [`WsSubscribeParams`][ws] |
| PostgreSQL wire `SUBSCRIBE` | Yes, SQL `SUBSCRIBE name AS OF EPOCH n`, including the committed cluster backend. | Supports `WHERE` and parses `WITH (…)`. Six trailing text metadata columns remain fixed: `__laminar_kind`, `__laminar_epoch`, `__laminar_checkpoint_id`, `__laminar_log_sequence`, `__laminar_row_index`, `__laminar_through_sequence`. Cluster partition metadata is not injected into SQL rows. Extended execution/FETCH stays positive and bounded. | [`SubscribeStatement` and parser][subscribe-parser], [`pgwire/subscription.rs`][pgwire-subscription], [`pgwire cursor`][pgwire-cursor] |
| HTTP SQL | No subscription execution. | Direct/cursor `SUBSCRIBE` is rejected in `/api/v1/sql`. | [`LaminarDB::execute`][db-mod] |

Pgwire simple-query `SUBSCRIBE` is rejected as unbounded. Extended query execution must request a positive bounded `Execute(max_rows)`, or clients can use an explicit transaction cursor and bounded `FETCH`. [`pgwire/dispatch.rs`][pgwire-dispatch], [`pgwire integration tests`][pgwire-tests]

Discrepancy: the SQL parser preserves `WITH ('snapshot'='true')`, but `open_portal_for_subscribe` does not inspect `SubscribeStatement.options`; at this commit that option still has no execution effect. Both WebSocket and pgwire use the same backend-neutral `SubscribeStart::AsOfEpoch` path. [`subscribe_parser.rs`][subscribe-parser], [`open_portal_for_subscribe`][pgwire-subscription], [`LaminarDB::open_subscription`][db-mod]

## Connectors and admission

Cluster admission additionally requires: no `best_effort`; a Splittable source; replayability for non-best-effort; exact source certification for exactly-once; a MultiWriter sink; non-ephemeral sink for at-least-once; CheckpointCommittable plus cluster exact certification for exactly-once; and FullChangelog acceptance when the pipeline emits a changelog. [`source_admission.rs`][source-admission], [`sink_admission.rs`][sink-admission]

The server default delivery guarantee is `at_least_once`, including standalone mode. Ephemeral sources/sinks therefore require an explicitly compatible delivery configuration; “single node” does not automatically mean best-effort admission. ## Differences from the old console

The previous console was not a safe description of this contract. This branch changes it as follows:

- Uses port 8080, the current server default, rather than README port 8000.
- Removes the nonexistent `/api/v1/queries` dependency and static connector capability claims.
- Handles `Stopped` as a reachable `503 /health`, distinguishes readiness, and probes a protected route so a wrong token cannot appear connected.
- Sends no bearer token to public probes, keeps the console token in session storage, migrates/removes the old persistent token, validates base URLs, and uses query-token auth only for WebSocket upgrades.
- Parses exact integers losslessly; cluster IDs, assignment versions, checkpoint fields, SQL integer/decimal cells, and subscription cursors are not rounded by JavaScript.
- Uses the returned assignment map and ABI instead of assuming 256 vnodes; renders the actual five node lifecycle states and exact assignment participant/drain fields; removes Raft/partition-lease inventions.
- Makes pipeline cluster fan-out limitations explicit and requires confirmation for lifecycle mutations.
- Replaces the old WebSocket request/response assumptions with the server's one-target-per-socket, server-only application protocol; validates all four outbound frames, bounds retained UI rows, and resumes only after explicit operator action from a progress epoch.
- Enables the feature branch's checkpoint-committed cluster subscriptions for stream targets while leaving cluster MVs unavailable. Durable replay deduplication uses generation/partition/partition-sequence/row-offset identity, the result view exposes partition metadata, and the UI explicitly rejects any inference of cross-partition order.
- Separates HTTP SQL from WebSocket subscriptions and changes local versus cluster tail/replay guidance instead of treating them as one storage model.
- Treats checkpoint status as one current row, handles structured checkpoint failures, uses real checkpoint/state metrics, and documents automatic rather than manual restore.
- Drives connector choices from `/api/v1/connectors`, redacts secret-looking connector properties and SQL in display surfaces, and avoids claiming delivery guarantees the endpoint does not carry.
- Uses only registered metric names, tolerates valid Prometheus non-finite values without charting them, and keeps raw metric discovery available.
- Adds keyboard/focus-safe dialogs, semantic tables/status regions, visible focus, reduced motion, responsive layout, accessible chart summaries, automated protocol fixtures, and axe smoke tests.

## Verification gaps and unsupported boundaries

- The protocol and UI fixtures are pinned to the feature SHA, but this console review did not create a new running multi-node/MinIO subscription soak or external Kafka, NATS, PostgreSQL, MongoDB, Delta, Iceberg, OTel, or WebSocket service matrix. Cluster behaviour was traced through the production implementation and its HTTP, database, recovery, fault, and soak suites; the feature branch's own CI remains the merge gate.
- The console cannot verify a server's commit SHA because the server exposes only the semantic version. Artifact/deployment attestation remains an operator responsibility.
- Feature-reduced or custom-connector server builds can return a different connector catalog and metric set. The UI renders discovery dynamically but cannot infer custom delivery contracts because `ConnectorInfo` does not expose them.
- Cluster diagnostics are intentionally not rendered or stored by this browser console: they sit outside console CORS, may use a separate high-sensitivity token, and expose process authority evidence. Use an authorised loopback diagnostic client and the schema-versioned envelopes.
- Pgwire was reviewed for the cross-transport resumption question but is not exercised by a browser SPA. This console does not act as a PostgreSQL client.
- Browser WebSocket APIs do not reveal failed-upgrade bodies/status, so detailed `400`/`404`/`409`/`410`/`500`/`503` diagnostics require server logs or a non-browser client. The catalog REST shape does not expose a subscription-capability flag, so the console can exclude cluster MVs but must let the engine perform exact stream-plan admission.
- The reviewed SHA is an unmerged feature-branch object. It must be replaced by the eventual merge commit (and the delta rechecked) before claiming a `main` pin.
- Cluster subscription support is intentionally limited to named non-windowed managed keyed aggregate streams. Stateless streams, global aggregates, raw joins, windows, MVs, arbitrary UDAFs, live relay, durable named-consumer acknowledgement, emitted/accepted resume tokens, and global total order are unsupported and are not emulated by the console.
- Manual `RESTORE FROM CHECKPOINT`, live source/sink/table topology DDL, connector capability discovery through REST, checkpoint history, and state-tier/budget-limit metrics remain unsupported.
